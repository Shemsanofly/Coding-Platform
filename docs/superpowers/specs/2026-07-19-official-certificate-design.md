# Official Certificate Design

## Objective

Upgrade the existing LearnCode certificate system so eligible students receive an official, printable Certificate of Completion generated from trusted backend records and downloadable as a one-page A4 landscape PDF.

## Current Context

The backend is Django and DRF. Certificate metadata already exists in `progress.Certificate` with unique `certificate_number`, unique `verification_code`, and one certificate per enrollment. Certificate eligibility is enforced server-side in `progress.services.certificates` using enrollment, lesson progress, and final quiz results. ReportLab is already used for PDF generation.

The frontend is React/Vite with Tailwind. Student certificate actions already exist on the course detail and certificate list pages. Public verification already works without login at `/verify-certificate/:verificationCode`.

The platform brand is LearnCode. Available colors include navy/ocean `#102c3d`, ocean `#15608d`, gold `#d9a441`, cream `#fffdf9`, sand `#f7efe6`, reef `#d8eef6`, and ink `#10212f`. No real logo PNG or CEO signature PNG was found in the project, so backend-owned placeholder image assets will be added.

## Design

The backend remains authoritative. The frontend may request generation, preview metadata, and PDF download, but it never submits student names, course titles, CEO details, verification URLs, or asset paths. The generation service loads the student, course, enrollment, instructor, completion date, platform details, and verification URL from trusted server-side state.

The official PDF uses ReportLab in A4 landscape. It has a white or very light cream background, navy primary text, gold accents, a double-line border, a centered formal wording block, a functional QR code at the lower left, a subtle official seal near the bottom center, and a CEO signature section at the lower right. The PDF is designed to fit exactly one page and handle long names and course titles through wrapping and bounded font-size reduction.

The certificate wording is:

`THIS IS TO CERTIFY THAT`

`[STUDENT FULL NAME]`

`has successfully completed all the prescribed requirements for the course`

`[COURSE TITLE]`

`and is hereby awarded this Certificate of Completion in recognition of dedication, achievement, and successful completion of the programme.`

## Data Model

`Certificate` will retain existing public uniqueness constraints. It will also snapshot official display fields needed for stable future verification and downloads:

- `completion_date`
- `platform_name`
- `platform_website`
- `instructor_name`
- `course_duration`
- `verification_url`
- `ceo_name`
- `ceo_title`
- `revoked_at`

CEO fields are generated by backend settings and are not user-editable through student or public endpoints.

## Public Verification

The public endpoint accepts only the verification code. For active certificates, it returns safe registry information: valid status, student full name, course title, issue date, certificate number, status, and platform name. For revoked certificates, it returns a revoked status and certificate number without treating the certificate as valid. For unknown codes, it returns a not-found status without exposing internal identifiers.

## Security

Certificate numbers and verification codes are generated on the backend. Verification codes use cryptographically secure randomness and never expose database IDs. Certificate creation occurs inside a transaction with enrollment locking and the database unique enrollment constraint prevents duplicates. Students can only download their own certificates; admins can download and revoke. Revocation is logged.

File access is constrained to the certificate `FileField` path, and download filenames are sanitized before being placed in `Content-Disposition`.

## Frontend

The student certificate list and course detail pages link to a read-only certificate preview. The preview shows an HTML approximation of the official PDF, verification status, certificate details, and a Download PDF button. Public verification keeps working without authentication and displays valid, revoked, and not-found states clearly.

## Testing

Backend tests cover eligibility, duplicate prevention, uniqueness, QR URL content, public verification states, download authorization, long names/titles, missing asset fallbacks, filename sanitization, and one-page A4 landscape PDF output. Frontend verification is covered by build checks and manual browser/PDF inspection in this environment.
